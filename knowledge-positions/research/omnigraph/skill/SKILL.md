# Knowledge Positions — just in time

Knowledge = { Position. Relation. Proximity. Resonance. }. Position means where and within where; relation means qualified connections; proximity means clustering in a declared space; resonance means importance learned through use (research, not implemented).

**Never reload the corpus or cookbook by default.** Begin with the human's prompt, current working context, and any JIT packet already supplied. Pass these ordered decision gates, stopping as soon as sufficient:

1. Reuse known knowledge in context.
2. Access an already-known ID or source coordinate directly.
3. Inspect only the immediate relations needed.
4. Discover by subject only if the other gates cannot answer.

A fresh session with relevant host-supplied context starts at gate 1. Without a host packet, skip empty gates and discover only if the task warrants it. Do not redo a host search. Do not fetch a full inventory, enumerate unrelated realms, reload already-read material or traverse multiple hops by habit.

Use the native OmniGraph skill only for the specific engine operation needed. Read [capture and contribution](references/capture.md) only when invoking the adapter. Read [native operations](references/operations.md) only for configuration, branches or recovery. Read the bundle RUNBOOK.md only on installation or repair.

Keep domain residence meaningful. Read and hash-check relevant evidence before reliance, but reuse previously verified unchanged spans and known coordinates. After meaningful work, capture useful new findings and qualified relations without waiting for the human to request writeback. If no durable contribution exists, do not manufacture one. Admission is touch 1; two refinements are permitted, then grow outward. Do not use an embedding provider or synthetic semantic inference. Native policies and collaboration remain in charge.
